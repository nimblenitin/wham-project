================================================================
1. WHAT IS WHAM
================================================================

WHAM (Whale Audio with VampNet) is a pipeline that:
- Extracts neural embeddings from whale audio using VampNet
- Generates synthetic whale call pseudocodas using a coarse-to-fine
  autoregressive codec model
- Evaluates generated audio quality using Fréchet Audio Distance (FAD)

It was designed for the DSWP (Deep Sound Whale Project) dataset
containing ~300 whale audio recordings.

5. WHAT WE DID — STEP BY STEP
================================================================

STEP A: EXTRACT EMBEDDINGS FROM DSWP AUDIO
  Script:  ~/wham_project/wham/extract_dswp_embeddings.py
  Input:   vampnet/data/testing_data/dswp_subset/*.wav (243 files)
  Output:  ~/wham_project/wham/embeddings/*.npy (243 files)
  Device:  MPS (confirmed via log output)
  Time:    ~17 minutes

  How it works:
  1. Loads VampNetWrapper with coarse + c2f weights on MPS
  2. For each WAV file:
     a. Reads audio with soundfile
     b. Converts to mono if stereo
     c. Resamples to 16kHz if needed (librosa)
     d. Converts to torch tensor (1, N_samples)
     e. Runs wrapper(audio_tensor) on MPS
     f. Output shape: (1, seq_len, 1280) float32
     g. Saves as .npy file

  Key deviation from notebook:
  - Used wrapper.forward() (i.e. wrapper(audio)) NOT wrapper.encode()
  - VampNetWrapper has no encode() method
  - Input must be raw 16kHz audio tensor, not AudioSignal object

STEP B: GENERATE PSEUDOCODAS
  Script:  ~/wham_project/wham/vampnet/batch_generate.py
  Input:   Embeddings from STEP A (used as conditioning)
  Output:  ~/wham_project/wham/generated_audio/pseudocoda_*.wav (20 files)
  Device:  MPS (confirmed via log output)
  Time:    ~14 minutes (~42s per file)

  How it works:
  1. Loads VampNet Interface on MPS with argbind
  2. For each embedding:
     a. Loads the .npy embedding
     b. Converts to torch tensor, moves to MPS
     c. interface.preprocess() — prepares latent representation
     d. interface.encode() — encodes to discrete codes
     e. Creates pmask (perturbation mask) for diversity
     f. interface.coarse_vamp() — autoregressive sampling
     g. interface.to_signal() — decodes codes to audio waveform
     h. Saves as WAV file

  Key deviation from notebook:
  - Rewrote batch_generate.py to match app.py's _vamp() pattern
  - Used interface.preprocess/encode/coarse_vamp/to_signal pipeline
  - Not a non-existent wrapper.encode() API

STEP C: COMPUTE FAD SCORE
  Script:  ~/wham_project/wham/compute_fad.py
  Input:   Real embeddings (from STEP A) + generated embeddings
  Output:  FAD score printed to stdout
  Device:  CPU (NumPy/SciPy — no GPU needed)
  Time:    ~4 minutes (3.8 min encoding generated + <1s FAD calc)

  How it works:
  1. Loads 50 cached real embeddings from .npy files
     - Each shape (1, N, 1280) → squeeze → mean-pool → (1280,)
  2. Encodes 20 generated WAV files through VampNetWrapper
     - Same process as STEP A but for generated audio
     - Caches result to gen_embeddings.npz
  3. Computes FAD (Fréchet Audio Distance):
     - mu_real = mean of real embeddings (1280-dim)
     - mu_gen = mean of generated embeddings
     - sigma_real = covariance matrix of real embeddings
     - sigma_gen = covariance matrix of generated embeddings
     - FAD = ||mu_r - mu_g||² + Tr(sig_r + sig_g - 2*sqrt(sig_r @ sig_g))

  Note: fadtk CLI was BROKEN on this platform due to:
  - torchcodec native .dylib incompatible with macOS ARM64
  - clap-laion-audio model fails with SSL certificate error
  - All fadtk models require torchcodec which doesn't work

  Solution: Computed FAD manually using our own VampNet embeddings
  with scipy.linalg.sqrtm for the Frechet distance formula.

8. ISSUES ENCOUNTERED & RESOLUTIONS
================================================================

Issue 1: "from wam import" fails
  Cause:   Directory is "wham" not "wam"
  Fix:     Changed import to "from wham import"

Issue 2: "collections.MutableSequence" deprecation error
  Cause:   Python 3.10 removed direct access on collections
  Fix:     Changed to collections.abc.MutableSequence

Issue 3: torch.load() weights_only error
  Cause:   PyTorch 2.x defaults to weights_only=True
  Fix:     Added weights_only=False explicitly

Issue 4: huggingface-hub API breakage
  Cause:   Newer versions changed API
  Fix:     Pinned to huggingface-hub<1.0

Issue 5: wrapper.encode() does not exist
  Cause:   Notebook assumed wrong API
  Fix:     Used wrapper.forward() directly (wrapper(audio_tensor))

Issue 6: Audio must be 16kHz
  Cause:   VampNetWrapper expects 16kHz input
  Fix:     Added librosa.resample() to 16kHz

Issue 7: fadtk CLI completely broken
  Cause:   torchcodec .dylib incompatible with macOS ARM64
  Fix:     Computed FAD manually using scipy.linalg.sqrtm

Issue 8: SSL certificate error (clap-laion-audio)
  Cause:   Certificate expired on Zenodo download server
  Fix:     Skipped — used manual FAD computation instead
